# punchlist

**让大小模型在用户设定的预算内协作完成编程任务。**

[English](README.md) · [开发路线](docs/roadmap.md) · [首批任务](docs/backlog.md)

目前处于项目启动阶段：已有协议草案、示例计划、配置草案和协议检查脚本；还没有任务执行器、模型适配器或订阅额度接入，也没有实验证明节省效果。

用户可以设定目标，例如“本任务最多消耗订阅窗口总额度的 5 个百分点”。系统计划根据失败原因和预算，选择继续使用小模型、重写指令、升级大模型，或保留进度并停止。没有可靠的计量和单次调用限制时，这只能是控制目标，不能承诺绝不超限。

第一阶段优先实现预算观测、调用前预留、调用后结算、中断恢复，以及串行执行和任务相关验收。先接一个订阅编程工具和一个便宜 API 或本地模型；同时使用 ChatGPT/Codex 与 Claude 订阅仍是后续目标。

在 Python 3.11+ 环境中检查当前设计：

```bash
python -m pip install -r requirements-dev.txt
python scripts/check_protocol.py
```

检查脚本不会运行示例中的命令，也不会调用模型。通过测试仅表示相应检查通过，任务是否满足用户需求仍需单独验收。

首轮实验比较始终使用大模型、始终使用小模型、失败直接升级、先重写再试和按失败类型选择。规划、重试、重写和复核的费用全部计入；同时报告成功率、额度消耗、耗时及预算超限率。
